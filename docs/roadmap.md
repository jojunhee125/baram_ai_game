## 1. 도달할 게임 경험

- 같은 세계의 인물로 보이는 캐릭터와 24종 스킨을 선택한다.
- 무기를 들거나 옷을 바꾸면 필드 캐릭터의 모습이 달라진다.
- NPC에게 목표를 받고 준비한 뒤 사냥·드롭·성장을 경험하고 마을로 돌아온다.
- 전사·도적·주술사·도사의 역할 차이가 공격 방식과 협동에서 드러난다.
- 지역마다 몬스터 행동·재료·장비 목표가 다르고 보스가 다음 지역으로 이어진다.
- 파티·거래·제작·문파·대전으로 혼자 하는 사냥을 함께 사는 세계로 확장한다.

첫 플레이 목표안은 **20–30분의 마을 → 사냥 → 보상 → 장비 교체 루프**다. 현재 측정 결과가 아니다.
전체 직업·24종 완성·거래까지 기다리지 않고 대표 캐릭터와 작은 지역부터 플레이 가능하게 만든다.
당시 캐릭터의 픽셀 표현을 정밀 비교하되 원본과 픽셀 값이 동일한지를 성공 지표로 삼지 않는다.

## 5. 작은 출시 단위

### R01 — 한 장의 기준

- 날짜/출처가 확인된 시대 reference에서 몸/머리 비례·얼굴·외곽선·명암·발 위치를 기록한다.
- native 48×48은 현행 표시 크기에서 출발한 후보이며 당시 게임의 원본 크기라는 뜻이 아니다.
- 4방향 대기 master와 manifest부터 승인한다. 미확정 규격은 `[needs verification]`으로 남긴다.
- 현재 구현: `baram-adventurer.png`(1254×1254px)의 4×4, 313px frame을 48px로 표시하며 프레임별 foot을 적용한다. 4방향 대기와 걷기 `[1, 2, 3, 2]`를 player·NPC·선택창에 연결했다. 이전 48px `pixels.json`·compiler·`master-adventurer.png`는 legacy 제작 자료로 보존하며 현재 기본 이미지가 아니다.
- 공격·시전·피격·사망의 전용 원화는 미제작이며 idle fallback을 사용한다. 공격 판정과 기존 공격 효과는 유지한다. `native60`은 manifest 계약명이며 60프레임 제작 완료를 의미하지 않는다.
- 기존 [1x/4x 비교와 실제 맵 화면](master-adventurer.md)은 이전 master의 기록이다. 현재 생성 이미지와 목표 native pixel 품질 사이의 간극, 시대 reference 대조·사용자 외형 승인은 남아 있다. 원본과의 동일 품질을 약속하거나 R01 전체를 완료 처리하지 않는다.

### R05 — 직업에 따라 다른 판단

- 전사: 근접/버티기. 도적: 위치 선정/순간 공격. 주술사: MP 기반 원거리 공격. 도사: 회복/지원.
- 공통 MP·대상·cooldown과 직업당 핵심 스킬 1개부터 연결하고 다음 단위에서 보조 스킬 1개씩 추가한다.
- 치유·버프 조건은 서버가 판단한다. 시전 애니메이션이나 생성 영상이 타격 권한을 결정하지 않는다.
- 전직·승급·전체 스킬 트리를 최초 구현에 묶지 않는다.
- **2026-09-18 설계 문서 작성 완료(코드 미착수).** 직업은 독립 테이블 영속·재선택 불가, MP는 HP와 같은 세션 런타임(영속 안 함), 스킬 쿨다운은 평타와 별도 예산, 대상 선정은 서버가 하고 아군 대상 스킬만 `targetSessionId`를 받는다. PvP 경로는 만들지 않는다(R10). [R05 문서](r05-classes-and-skills.md)
- 구현은 **a(직업 저장·MP 자원·능력치 차이) → b(스킬 실행 계약·직업당 스킬 1개) → c(MP 게이지·단축키·시전 표현)** 세 단계로 나누며 각 단계마다 별도 승인을 받는다. 직업 전용 외형과 전용 시전 원화는 R02(아트)에 묶여 R05-c 범위 밖이며 fallback 효과를 쓴다.
- **2026-09-18 R05-a 구현 완료(서버·shared·선택 패널).** 직업 저장(`0011_player_class.sql`·`classStore.ts`, write-once), `Player.playerClass`/`PlayerSession.mp` 추가, `class:choose`/`class:changed`/`class:denied` 프로토콜, 직업별 HP·공격 배율과 MP 자원(`shared/src/classes.ts`)을 `totalAttack`/`totalMaxHp`/`totalMaxMp`에 연결하고, 되돌릴 수 없는 선택을 2단 확정으로 받는 클라이언트 패널을 붙였다. 미선택 계정의 배율은 정확히 1.0 — 기존 전투·레벨 테스트 전부 그대로 통과. 독립 검증이 Critical 1건(늦게 도착한 입장 조회가 방금 고른 직업을 되돌림)을 잡아 수정했다. 실 PostgreSQL 16으로 write-once 계약도 확인했다. 스킬(R05-b)은 이번 범위에 없다. 상세·검증 증거는 [R05 문서](r05-classes-and-skills.md) §6.

- 무기·상의·투구부터 제작하고 나머지 슬롯은 표현 필요에 따라 추가한다.
- Lv30을 출발점으로 유지한다. 확장은 성장 CLI의 처치 시간·소모품 비용·획득 속도 자료로 결정한다.
- 직업 선택 이후 전직·승급은 전용 퀘스트, 보스 조건, 새 스킬 해금을 묶어 한 단계씩 추가한다. 레벨 상한만 늘려 같은 사냥을 반복시키는 확장으로 끝내지 않는다.

### R07 — 지역마다 다른 사냥

- **2026-09-23 부분 구현:** 첫 사냥→굴→숲 퀘스트와 첫 보스의 타일 예고·회피·HP50% 2단계를 구현했다. 새 퀘스트 SQL 실DB 실행, 전체 테마와 보스 진행은 별도다. [구현 기록](implementation-2026-09-23-parallel-code-bundle.md)

- 테마당 일반 몬스터 2종·특수 1종을 후보로 두되 첫 테마부터 완성한다.
- 추적형·거리 유지형·예고 공격형으로 공략을 구분하고 지역 전용 재료와 장비를 연결한다.
- 첫 보스는 예고→공격→빈틈 하나부터 구현한 뒤 체력 단계 전환을 추가한다.
- 기존 사냥방 개수만으로 난이도 진행이 완성됐다고 보지 않는다. 장편 영상보다 읽히는 전투 예고를 우선한다.
- 마을 밖 연결 필드·휴식 거점·귀환 동선과 지역 NPC의 짧은 이야기를 함께 배치해, 사냥터가 독립된 전투방 목록으로만 남지 않게 한다.

### R08 — 같이 사냥할 이유

- 작은 파티의 생성·초대·탈퇴와 같은 지역 보상부터 구현한다.
- 기여/거리/접속 상태로 자격을 명시하고 회복·지원도 기여 규칙에 반영한다.
- 공동 처치 ID와 구성원별 정산 ID로 중복 지급을 막고 역할 협동으로 첫 보스를 완료하게 한다.

### R09 — 교환과 제작

- 직접 거래 1건의 양측 확정·취소·연결 종료 처리를 먼저 완성한다.
- 다음으로 제작법 1개의 재료 소비와 결과 지급을 원자적으로 연결한다.
- 거래소·경매·우편·오프라인 상점은 후속 수요로 결정한다. 재료 유입/소비 기록으로 경제를 조정한다.

### R10 — 오래 머무는 이유

- 문파 생성·가입·권한과 공동 목표 하나부터 제공한다.
- PvP는 별도 구역/규칙으로 시작해 PvE 수치·보상을 무조건 공유하지 않는다.
- 반복 보스·외형 수집을 endgame 후보로 두고 공성·대규모 전장은 이후 규모로 판단한다.
- 다중 process 운영 전에 성장·정산 상태의 process 간 일관성을 별도 설계한다.

## 6. 성능과 작업 비용

- AOI 시야 제한은 이미 있다. 새 공간 색인 작업으로 반복하지 않는다. [constants.ts](../shared/src/constants.ts)
- 지급·퀘스트·파티는 변경 이벤트로 갱신한다. `k = 영향받는 접속/대상 수`일 때 O(k)를 목표로 하며 전체 room/계정 순회를 피한다.
- 서버 tick에서 DB 조회·AI 생성·전체 콘텐츠 검증을 하지 않는다. 콘텐츠 규격은 가져오기/시작 단계에서 확인한다.
- 정적 장비는 offline atlas 합성, 동적 조합은 장비 변경 시 cache한다. 매 프레임 canvas 합성을 피한다.
- 현재 지역 preload·효과 pool·bounded cache를 사용한다. 모든 외형 조합 선적재를 기본으로 삼지 않는다.
- FPS·동접·메모리 개선 수치는 측정 전 주장하지 않는다. 실제 병목·구조 변경이 있을 때만 범위를 정해 측정한다.
- 문서·단순 수정·쉽게 되돌릴 시각 교체에는 테스트를 추가하거나 실행하지 않는다.
- 정산·거래처럼 영속 상태가 걸린 변경만 직접 위험 사례를 최소 검증한다. 전체 테스트·build·E2E 반복은 기본 절차가 아니다.

현재 생성 atlas는 [avatarArt.ts](../client/src/world/avatarArt.ts)의 `AVATAR_REPLACEMENTS`에 등록되어 있다. 최신 manifest 테스트는 통과했으나 전체 실제 플레이 검증과 시대 reference 픽셀 대조·사용자 시각 승인은 남아 있다. [master 제작·적용 기록](master-adventurer.md)
