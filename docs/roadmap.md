# 서버 작업 완료 기록

## 2026-09-14 — 동일 계정의 활성 접속 간 성장 정보 동기화 완료

- 공통 EXP cache에서 확정된 지급·사망 차감을 해당 계정의 활성 session에만 전달한다. 다른 room에서도 서버 EXP, 공개 level, 레벨에 따른 공격력·최대 HP가 일치한다. 장비와 현재 피해 상태는 session별로 유지하며, 레벨업 시에는 기존 전량 회복 규칙을 각 접속에 적용한다.
- 늦게 도착한 입장 snapshot이 새 지급·차감을 덮어쓰지 않도록 구독 version을 검사한다. 접속 종료·room 폐기 시 구독을 해제하고, 구독 callback 오류는 확정된 저장 결과에 영향을 주지 않는다.
- 계정별 구독 색인을 사용해 해당 계정의 접속 수에 비례해서 처리한다. 매 tick DB 조회, 전체 room 순회, 새 서비스는 추가하지 않았다.
- 검증: 신규 동기화 4개와 직접 관련된 기존 회귀 8개만 선택 실행하여 **12개 통과, 실패 0개**(약 0.9초). 서버 typecheck 통과. 전체 테스트·build·E2E·부하 테스트 미실행.
- 범위: 한 서버 process가 공유하는 `CachedProgressStore` 기준. process 간 동기화와 UI/HUD 즉시 갱신은 포함하지 않는다. 기존 EXP 지급 메시지는 실제 처치 session에만 보낸다. 다른 접속의 서버 능력치는 즉시 반영되며, 별도 EXP 지급 안내를 중복 발송하지 않는다.

## 2026-09-14 — EXP 오류 처리·고레벨 입장 HP 보정 완료

- EXP 저장 queue의 정리용 Promise에서 발생하던 추가 unhandled rejection을 제거했다. 원래 오류는 호출자에게 전달하며 같은 계정의 후속 작업은 계속 처리한다.
- PostgreSQL 공통 pool에 실행 제한 `statement_timeout=5,000ms`, 응답 대기 제한 `query_timeout=10,000ms`를 추가했다. 기존 연결 획득 제한 5초와 최대 연결 4개를 유지했다. 자동 재시도는 추가하지 않았다.
- 저장된 EXP로 레벨을 복원할 때 현재 HP에 최대 HP 증가분을 반영한다. 복원을 기다리는 동안 받은 피해·회복 결과를 유지한다.
- 검증: 신규 회귀 3개와 직접 영향받는 기존 사망 사례 4개만 선택 실행하여 **7개 통과, 실패 0개**. 서버 `typecheck` 통과. 독립 production 코드 리뷰에서 지적 사항 없음.
- 전체 테스트·build·브라우저 E2E·부하 테스트는 실행하지 않았다. 실제 PostgreSQL timeout은 미검증이며, 공통 pool 제한은 시작 시 migration·advisory lock에도 적용된다.
- UI 변경·배포는 포함하지 않는다. 보상 재시도/중복 방지와 다른 session의 성장 정보 동기화는 이번 완료 범위가 아니다.
